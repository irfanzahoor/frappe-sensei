      Limits — what this checker cannot do yet

      • FR-002 (another app's files edited): a path check only. It fires when a file path contains apps/frappe/, apps/erpnext/ and similar — loose pasted snippets with no app path cannot trigger it.
      • FR-007 (Custom Field not a fixture): a comment that merely talks about custom fields can false-positive. The fixtures/ path is the signal, not the code.
      • FR-018 (validation only in JS): a heuristic. A JS validate handler is flagged unless a .py file in the same check defines validate / before_submit / before_insert.
      • FR-023 (permission check): a helper the whitelisted method calls is followed — if that helper checks permission (directly or through another helper), the endpoint is not flagged. A helper in a file that was not submitted cannot be followed, so check the whole app when a blocker looks wrong. A function that only reads frappe.get_roles() and performs no database read or write is also exempt.
      • FR-013 / FR-031: creating a document is not reading or updating one. frappe.get_doc({...}).insert() does not fire FR-013, and .insert() inside a loop does not fire FR-031 — only .save() / .submit() do.
      • FR-030 / FR-031 do not fire in demo, seed or test files (demo/, tests/, test_, or a filename containing seed), where loops insert demo data by design. Other rules still apply there.
      • # noqa: a # noqa comment on the flagged line suppresses the finding, for every rule.
      • FR-030 / FR-031 (loop detection): loops are tracked by Python indentation, not a full parser. Unusual formatting can be missed.
      • GitHub URL tab: up to 300 files per run, fetched 10 at a time with live progress. The file list uses the public GitHub API, which allows only 60 requests/hour without a login — that quota is per IP address and shared by everyone on it, so it can run out even if you only fetched once. Paste a GitHub token above to raise it to 5,000/hour, or use the Upload folder tab instead — it has no limit. If a repo has more than 300 matching files, only the first 300 are listed — check a subfolder URL (e.g. github.com/owner/repo/tree/branch/food_manufacturing/api) or upload the rest.
      • Upload folder tab: pick a whole app folder from your computer — every .py / .js / .html file inside it is checked in one run, up to 500 files, with no GitHub API calls and no rate limit. Files keep their relative paths.
      • ZIP upload is not in this version — upload a folder instead. AI fix suggestions, private repos and logins are out of scope for the MVP.
